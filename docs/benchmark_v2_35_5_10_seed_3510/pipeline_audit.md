# Current Pipeline Audit

- Family manifest: `configs/benchmark_v2_50family/family_manifest.yaml`.
- Frozen primary split: `configs/benchmark_v2_50family/splits/primary_family_split.yaml`.
- Family IDs are `f001` through `f050`; workload IDs begin with `w001`
  through `w200`; package IDs are family/workload-specific `sample_uid` values.
- Canonical full-stage package indices are under
  `derived/indices/full_50x200/{sample_split,family_split}`. The family-split
  union is the authoritative 10,000-row inventory.
- Isolated-source rows already cover all 50 families under
  `canonical/stages/full_50x200/source_isolation`; no isolated HotSpot rerun is
  needed. These are representative source-isolation packages rather than all
  200 workloads per family, so source fitting follows the canonical
  family-aware 80/20 policy within the 35 allowed families (28 fit, 7 internal
  selection).
- Source training uses `train_source_response_model.py`; its response and input
  normalization are computed only from the supplied train index.
- Package training uses `train_residual_cnn.py`; raster, metadata, residual,
  resistance-head, and direct-target normalizers are computed from the
  supplied train index only.
- Source maps are checkpoint-dependent caches generated by
  `build_full_source_superposition_base.py`. A new 35-family source checkpoint
  therefore requires new source maps, but not new HotSpot labels.
- Familiar workload splitting is ordinal-based: 1-160 train, 161-180 internal
  validation, and 181-200 familiar test.
- `evaluate_residual_cnn.py` produces common grid and per-family metrics;
  `evaluate_integrated_chiptherm.py` is the authoritative uncached ChipTherm
  path.
- Existing Benchmark v2 wrappers deliberately enforce the primary 40/5/5
  protocol. The secondary builder does not weaken those checks; it creates
  separate versioned CSV views and invokes the shared low-level trainers.
- There is no general YAML inheritance engine. Secondary configs therefore
  record `base_config` provenance and repeat canonical values explicitly so a
  silent default change cannot alter the controlled comparison.

## Rebuild Matrix

| Artifact | Reuse or rebuild? | Reason |
|---|---|---|
| Package HotSpot labels | Reuse | Physical dataset is unchanged. |
| Isolated-source HotSpot labels | Reuse | Existing inventory covers all 50 families. |
| Context, metadata, graph tensors | Reuse | These are deterministic per-sample inputs. |
| Protocol CSV indices | Rebuild | Family and workload roles change. |
| Source-response normalizer/model | Rebuild | Learned from the 35-family training partition. |
| Source-superposition maps | Rebuild | They depend on the new source checkpoint. |
| Residual/CNN/FNO normalizers | Rebuild | Fit from the new 5,600-row training index. |
| Residual/CNN/FNO checkpoints | Retrain | Their optimization partition changes. |
